## 0. 座標の決め方（ゲームの外形との対応）

- 原点は `entrance_lecture` の真下の床。+Y が屋内の奥、Z が上（DESIGN.md §3.4）。
- ゲームの外形（CJ）: 南面は X −28.6 で Y 4.42、X 28.1 で Y 4.0 のゆるい斜め。入口の扉は南面の (0, 4.21)、entrance の Empty は (−0.02, 1.41)、開口は STANDARD（幅 3.2 m・高さ 2.6 m）。屋内の外接枠 `s.inner()` は X −32.88〜49.52、Y 4.3〜54.62。
- 外接枠の中でも外形の外になる所が 3 か所あり、床も壁も置かない（閉じる）:
  - 東側の南の縁 (28.82, 7.87)–(49.82, 8.59) より南
  - X < 35.6 で、北の外壁 (−28.8, 50.61)–(35.59, 50.14) の斜めの線より北
  - X < −28.6（西の外部階段の張り出し X −33.18〜−28.94、Y 28.73〜33.62 を除く）
- 北の外壁は外形どおりの斜めの線（X −28.8 で Y 50.61、X 35.59 で Y 50.14）にする。以下の表の「Y 50.6」はこの線のこと。
- **向き（確定）**: 講義棟は東西に長い中廊下型で、東端が金町駅側の正面、西端が図書館・学生食堂側（OC の「West = 図書館側、East = 正面入口側」、JSPE の「金町駅より」）。ゲームの入口は南面の中央なので、**実物の南入口（101 と 102 の間の「エントランス」）＝ゲームの入口**、**−X = 実物の西、+X = 実物の東**、**+Y = 実物の北**とした。
- **図からの写し（推定）**: JSPE p3 の切り出し（900 × 520 px）で、X = −28.6 + (px − 47) × 0.0955。1F・2F・3F の切り出しで同じ式が通る（3F は 1 px 東へずれる）。Y は図の南の外壁・北の外壁を外形の Y 4.3・50.6 に合わせ、Y = 50.6 − (py − py₀) × 0.1068（py₀ は北の外壁の行: 1F 38.5、2F 65.5、3F 54）。外形は OSM 由来で、図の比率のままだと南北に外形が余るため、南北だけ 1 割強伸ばしている。
- この式で読んだ南北の割り付け（1F〜3F 共通）: 南の室 Y 4.3〜19.8、南廊下 19.8〜23.5、中央コア 23.5〜31.5、北廊下 31.5〜35.1、北の室 35.1〜50.6。南の室と北の室は同じ奥行き（15.5 m）、廊下は両方とも 3.6 m。
- 実寸の幅（推定）: 東西 78.1 m（X −28.6〜49.5）。図の 101 の東西幅は 21.3 m で、下の 101 の内法 20.9 m と合う。
- **4F〜7F の写し（推定、#279）**: JSPE p4 の描き直し `jspe_kaijo_p4.png` で X = −28.6 + (px − 295) × 0.1062。2F の北の並びは ISIJ `isij_map_p2.png` の 3F の行で X = −28.6 + (px − 333) × 0.1336（西の外壁 px 333、311 の東の壁 px 815 = X 35.8）と、`jspe_kaijo_p3.png` の X = −28.6 + (px − 294) × 0.1053 の 2 つで読み、差が 0.5 m より小さいことを確かめた。南北の割り付けは 4F〜7F も 1F〜3F と同じ（JSPE p4 の廊下とコアの線が p3 と同じ比率に並ぶ。確定）。

### 7-3. 上限の提案

- `INT_BUDGET_ONE["lecture"]` を **55,000 → 110,000** にする（コード側の作業。`blender/build_interiors.py`）。見込み 89,700 に対して予備は約 20,300（中を作る部屋を後で 1〜2 室足す分と、看板の文字の実測が見込みより多い分）。
- 屋内の合計: 今の実測 307,074、上限 `INT_BUDGET` 450,000 なので余裕は 142,926。
  - 上限を上げる分 66,300 は、その余裕の約 46%。
  - 見込みの増分 46,000 は、余裕の約 32%。合計は約 353,000（上限の約 78%）になる。
- `over_budget()` は棟ごとの上限（`INT_BUDGET_ONE`）と屋内の合計（`INT_BUDGET`）を別々に見るので、両方が通ることを確かめる（§11）。
- 見込みを超えたときの削り方（効く順）:
  1. 型 A の机と長椅子を 1 つの箱にまとめる（3 席 24 tris。5 室で約 5,000 浮く）。
  2. 7F の白い札と閉じた扉を省き、壁だけにする（約 600）。
  3. 中を作る小室（410・509・610）の 1 つを閉じる（約 600）。
- 同じ型の部品（3 人掛けの机、PC の机、閉じた扉、室名札の板、手すり壁の区間）は同じ関数で同じ形を作り、繰り返しにしておく。Unity の GPU instancing や共有メッシュに替えると描画の負荷は下がるが、書き出しの tris の数え方は変わらないので、上の見込みは 1 つずつ数えた値のまま。
- 席は低ポリにする（1 席 16 tris。101 の `hall_seat` の 44 tris は使わない）。

### 7-4. WebGL の容量

- 今のビルドは約 66 MiB で、上限は全体 80 MiB・data 64 MiB。余裕は全体 約 14.1 MiB、data 約 8.7 MiB。
- 屋内のメッシュは 1 tri あたり約 35 B なので、+46,000 tris で約 +1.5 MiB（data の余裕の約 18%）。
- 新しいテクスチャは使わない（§2 の材質はすべて単色）。看板の文字もメッシュなので容量はこの見込みに含まれる。
