# キャラクター生成（`build_characters.py`）

Blender 4.5 LTS を headless で回し、アニメ調の 3D キャラクター 7 体を
リグ・シェイプキー・アニメーション・トゥーン輪郭線付きで FBX へ書き出す。
`bpy.ops` はほぼ使わず、頂点／面／マテリアル名を NumPy で積んでから
`from_pydata` + `foreach_set` で一括生成するので、1 体あたり約 1 秒で完成する。

## 実行

```bash
"/c/Program Files/Blender Foundation/Blender 4.5/blender.exe" -b \
  --python blender/build_characters.py -- \
  --ids mirai,botchan,madonna,inari,kaname,sora,prof \
  --preview --preview-dir "<repo>/docs/previews"
```

| 引数 | 既定 | 説明 |
|------|------|------|
| `--ids` | 全 7 体 | 生成するキャラクター ID をカンマ区切りで指定 |
| `--out-dir` | `unity/KatsushikaCampusDays/Assets/Models/Characters` | FBX と各種 PNG の出力先。無ければ作る |
| `--preview` | オフ | `docs/previews/<id>_{front,side,back,turn,walk,face}.png` を描画する |
| `--preview-dir` | `docs/previews` | プレビューの出力先。**絶対パスで渡す**（相対パスは blend ファイル基準に解決される） |
| `--face-size` | `2048` | 顔テクスチャの 1 辺のピクセル数 |
| `--no-outline` | オフ | 輪郭線シェルを作らない（三角形数を半減させたいとき） |
| `--no-verify` | オフ | FBX 再インポートによる検証を省く（調整の反復用） |

## 所要時間（Blender 4.5.10 LTS・Windows 11 での実測）

| 内容 | 時間 |
|------|------|
| 1 体のメッシュ生成〜FBX 書き出し | 1.06〜1.20 秒 |
| 7 体（プレビューなし、FBX 再インポート検証あり） | 13.2 秒 |
| 7 体 + プレビュー 42 枚（Eevee Next） | 24.5 秒 |

## 出力

- `<out-dir>/<id>/<id>.fbx` — メッシュ 2（本体 + 輪郭）+ アーマチュア 1。
  Y-up / -Z-forward。`bake_anim_use_all_actions=True` で 6 本の Action を焼く。
- `<out-dir>/<id>/face.png` — 2048x2048。虹彩のグラデーションと放射状の繊維、
  ハイライト 2 個、まつげ、眉、口、頬の赤みを NumPy で描画し
  `img.pixels.foreach_set` で流し込む。
- `<out-dir>/<id>/{kasuri,yagasuri}.png` — 和柄。十字絣と矢絣を Python で
  描画し、Generated 座標の正面投影でタイリングする。
- `docs/previews/<id>_{front,side,back,turn,walk}.png` — 960x1280、Eevee Next
  （失敗時は Cycles → Workbench）。3 点照明 + 柔らかい床影。
- `docs/previews/<id>_face.png` — 顔アップ 1280x1280。85mm 相当の望遠で寄るので
  鼻や頬が広角で伸びない。

### 走りのフィルムストリップ（`tools_view/run_strip.py`）

腕の振りや重心のブレのように「動きの形」を見たいときは、1 コマのプレビューでは
足りない。`Run` の 1 周期を前・横・後ろから連番で描いて 1 枚につなげる。

```bash
"/c/Program Files/Blender Foundation/Blender 4.5/blender.exe" -b \
  --python blender/tools_view/run_strip.py -- \
  --id mirai --out-dir "<repo>/docs/previews"
```

- 出力は `docs/previews/<id>_run_{front,side,back}.png`（420x560 のコマを
  クリップのフレーム数だけ横に並べた 1 枚。mirai なら 10 コマ = 4200x560）。
- `--arm 52 --elbow 66,34` のように渡すと `Run` の腕の値だけ差し替えて描ける
  （#43 の修正前と並べて比べるため）。`--tag before` でファイル名に接尾辞が付く。
- 作業用の仮 FBX とコマ単位の PNG は OS の一時ディレクトリに置いて最後に消す。

## 顔の設計根拠

アニメ調の顔は「人間の顔をローポリにしたもの」ではなく、**線で描かれた絵を
立体に置き直したもの**として作る。調査した実制作の記事はどれも、目・まつげ・
眉・二重を顔面の連続したポリゴンで表さず、顔から切り離した面として扱う点で
一致していた。本実装もそれに従い、`body.py` で顔の各パーツを独立したリボン
／ディスクとして頭部表面の少し手前に置いている。

- **目・まつげ・二重・眉は別メッシュにする。** Autodesk のセルルック講座は、
  眉・眼窩・二重・キワの 4 本のラインを顔面から切り離し、元の位置よりわずかに
  手前へ置いて穴を塞ぐ手順を取る。表情変形を見越してラインを等間隔に割るとも
  述べている。本実装の `_ribbon()` はこれをそのまま実装したもので、まつげ・
  二重・眉を `off_lash` / `off_brow` だけ法線方向に浮かせた帯として作る。
  <https://area.autodesk.jp/column/tutorial/maya-celllook-character/04-express-eyes-02/>
- **ローポリではまつげ・眉・二重を板ポリにした方が表情を作りやすい。**
  <https://polygolog.com/face-parts-modeling/>
  まつげをカーブ + ベベルで断面を持たせる作り方もあるが
  （<https://signyamo.blog/3d_eyelashes/>）、ゲーム用の予算では板で足りる。
- **顔トポロジには 4 つの型がある**という整理を参考に、口の開閉を伴う
  タイプではなく「口は小さな面、目は別メッシュ」の型を選んだ。
  <https://animecglab.com/en/4-categories-of-face-topology-in-anime-3d-model/>
- **目の縦横比と位置。** 大きく丸い目は縦横 1:1、標準的な目は 2:1 に近い。
  目の高さは耳の上の付け根あたり、すなわち頭部の縦中心のやや下に来る。
  <https://ani-emo.com/archives/2484> /
  <https://www.palmie.jp/lessons/301> /
  <https://comic.smiles55.jp/guide/7615/> /
  <https://kurosaki-coco.com/illustration-course-eye-balance>
  本実装は `params.py` の `eye_ry / eye_rx` を縦長側に取り、目の中心を
  頭頂から見て中心よりわずかに下（`eye_y`）へ置いている。ビルドしたメッシュ
  から測ると、白目の縦横比は美少女 6 体で 1.06〜1.13、まつげを含む目の幅は
  同じ高さで測った顔の正面幅の 1/4.0〜1/3.5 に収まる（`prof` は成人男性
  なので縦横比 1.03、幅 1/4.1 と丸みが控えめ）。
- **かわいさは「パーツを顔の中央ラインより下に寄せ、鼻と口を小さくして
  視線を目へ集め、顎を短くする」ことで出る。**
  <https://quirkydrawingclassroom.com/draw_anime_character_face>
  これに従い、鼻は `eye_y * 0.66`、口は `eye_y * 0.46` の高さに、鼻は
  「あるのが分かる程度」のごく浅いふくらみ、口は口角を上げた小さな帯にした。
  頬の赤みは顔テクスチャ側で目の下に淡く乗せる。
- **虹彩は単色で塗らない。** 顔テクスチャ（`tex.py`）で放射状の繊維と
  上暗下明のグラデーションを描き、ハイライトを大小 2 個（上に大きい円、
  反対側の下に小さい円）置く。2048px あるので瞳の中の階調が潰れない。

実装上の制約: **眉は前髪の後ろに隠れる。** 「前髪の上に眉を描く」のは
2D の絵では定番だが、3D でやるには深度テストを無視するシェーダが要る。
眉メッシュを前髪より手前へ動かすと横顔で額から浮いて破綻するため、
本実装では眉を顔面から数ミリ浮かせるに留め、前髪に隠れる位置に置いた。
この表現は Unity 側のマテリアル（`ZTest Always` + レンダーキュー）で解く。

## 頭身の設計根拠

`docs/ref/tus_chara01.jpg`（坊っちゃん）と `docs/ref/tus_chara02.jpg`
（マドンナちゃん）のマスコットは、頭が体と同じくらい大きいデフォルメ体型で、
実測すると頭の直径が全高のおよそ 1/3 を占める。そこで 2 体を **約 3 頭身**
（身長 1.15 m / 1.14 m、頭の直径 ≒ 身長 ÷ 3）に再設計した。

- **3 頭身は「頭 1 : 胴 1 : 脚 1」。** 2 頭身なら頭 1 : 胴 0.5 : 脚 0.5。
  <https://www.palmie.jp/lessons/94>
- **3 頭身では 2 つ目の丸が上半身、3 つ目が下半身にあたり、腕は肩から
  お尻の下あたりまで伸ばす。** 手足は短いが、太くはしない。
  <https://atam-academy.com/blog/30221/> /
  <https://atam-academy.com/blog/48785/>
- **髪は素体の頭部よりひとまわり大きく作り、首はほとんど描かず、なで肩にする。**
  <https://www.clipstudio.net/oekaki/archives/153412> /
  <https://tips.clip-studio.com/ja-jp/articles/10582>
  本実装では `params.py` の `chibi_m` / `chibi_f` で首の長さをほぼ 0 にし、
  肩の傾斜を強めている。

**太らせない**という要求に対しては、頭幅を 1 とした比で寸法を管理している
（`params.py` の `BUILDS` は頭幅単位）。ビルド後の実メッシュから測った値:

| id | 頭幅 m | 肩幅 m | 肩幅 / 頭幅 | 腕の直径 m | 腕 / 頭幅 |
|----|--------|--------|-------------|------------|-----------|
| `mirai` | 0.223 | 0.321 | 1.44 | 0.046 | 0.208 |
| `botchan` | 0.368 | 0.440 | 1.19 | 0.077 | 0.208 |
| `madonna` | 0.352 | 0.391 | 1.11 | 0.072 | 0.204 |
| `inari` | 0.216 | 0.311 | 1.44 | 0.045 | 0.208 |
| `kaname` | 0.226 | 0.325 | 1.44 | 0.047 | 0.208 |
| `sora` | 0.218 | 0.328 | 1.50 | 0.046 | 0.208 |
| `prof` | 0.235 | 0.392 | 1.67 | 0.049 | 0.208 |

美少女キャラは肩幅が頭幅の 1.6 倍以下、腕の直径は全員 0.22 倍以下。`prof` は
成人男性なので 1.67 倍を許容している。肩幅は髪パーツを除いて測る
（`inari` のツインテールは横へ 0.20 m 張り出すため、含めると 1.87 倍になる）。

## 輪郭線（`outline.py`）

本体メッシュを複製し、頂点法線方向へ身長 × 0.0022 だけ膨らませてから面を
裏返す、いわゆるインバート・ハル方式。Unity 側で通常の背面カリングを効かせると
シルエットの外側だけが黒く残る。

- <https://dskjal.com/blender/edge-detection> — ソリッド化／ディスプレイスで
  法線反転メッシュを作り、裏面を描画しないマテリアルを当てる。
- <https://www.tomog-storage.com/entry/Blender-Beginner-HowMakeOutLine> —
  法線反転 + マテリアルインデックスのオフセット + 裏面非表示。
- <https://sd-robbit.com/blender_tips0/> — 頂点ウェイトで線幅を場所ごとに変える。

顔のパーツ（白目・虹彩・まつげ・二重・眉・鼻・口）は頭の表面から数ミリしか
浮いていないため、頭の膨張シェルが前へ回り込んで目を黒く塗り潰す。膨張量を 0 に
するだけでは反転した複製が同じ位置に残って Z ファイティングになるので、
複製メッシュから該当頂点を bmesh で削除している（`SKIP_PARTS`）。
複製は `obj.copy()` なので頂点グループとアーマチュアモディファイアを受け継ぎ、
本体と同じスキニングで動く。Shape Key は輪郭には不要なので落とす。

## リグ・シェイプキー・アニメーション

- ボーンは `docs/DESIGN.md` §2.1 の Unity Humanoid 22 本ちょうどに、髪揺れ用の
  `HairFront` / `HairBack`（`Head` の子）を足した 24 本。`Hips` が根の A ポーズ。
  `ARMATURE_AUTO` の Bone Heat Weighting は多シェル構成だと解が出ない
  （ゼロウェイト率 100%）ので、それを検知して距離ベースへ自動フォールバックし、
  髪・スカート・袴の下端は `rig.override_weights` で親ボーンへ寄せる。
  距離ウェイトだと靴下・ズボン・素肌の内ももが逆の脚へ 5 割近く乗るので、
  `_l` / `_r` の付くパーツからは反対側の脚ボーンを外す（`_keep_leg_side`）。
- **衣装は必ず 1 頂点 2 ボーンに収める（`_cloth_leg_weights` / `_prune_influences`）。**
  WebGL 版が使う品質レベル Mobile は `QualitySettings.skinWeights = 2`
  （PC は 4）なので、3 本以上のウェイトはビルド時に上位 2 本へ切り詰められて
  PC 版と形が変わる。以前の `_hakama_weights` は最近傍の素肌ウェイトを転写して
  いたため botchan の袴は 1 頂点 6 ボーン・madonna は 5 ボーンあり、Run の
  最大開脚フレームで 7.29 cm ずれていた。
  いまはスカート・エプロン・白衣・袴・ズボンの尻を **Hips ＋ 脚ボーン 1 本**
  だけで包む。左右は x=0 で割らず、胴の中心から見た向き（ヒダの凹凸で動かない
  量）で `band` の幅だけ脚寄せを 0 まで落とすので、中央ではどちらの脚を選んでも
  Hips 100% に一致し、切り詰めても形が変わらない（全 7 人・全衣装で 2 ボーン
  化による差は 0.02 cm 以下）。袴だけは膝の上下で UpperLeg / LowerLeg を
  切り替え、その面でも同じ理由で脚寄せを `knee_keep` まで落とす。
  靴下・ズボン・ブーツの筒は距離ウェイトのまま 3 ボーン乗ることがあるので
  `_prune_influences` で上位 2 本へ間引く。調整値は `rig.CLOTH_LEG`。
  エプロンは下のスカートと同じ高さ・同じ割合で脚へ寄せる（別の割合にすると
  ヒダの尾根がエプロンを突き抜ける）。
- シェイプキーは `blink_L` / `blink_R` / `smile` / `mouth_open` / `mouth_a` /
  `mouth_i` / `angry_brow` の 7 種。メッシュのパーツ名（`mb.part_indices`）で
  対象頂点を引いて動かす。
- Action は `Idle`(60f ループ) / `Walk` / `Run`(どちらもループ) / `Jump`(18f) /
  `Wave`(40f) / `Talk`(60f) の 6 本。`Walk` と `Run` の長さはキャラの脚長から
  決まるので人によって違う（実測: 低頭身の botchan・madonna が `Walk` 10f /
  `Run` 8f、mirai ら 4 人が 14f / 10f、いちばん脚の長い prof が 15f / 11f。
  ループ用に同じ姿勢の最終キーがもう 1 枚付く）。
  クリップの前進速度をゲーム側のブレンドツリーの閾値（`Walk` 2.6 m/s、
  `Run` 5.4 m/s）に合わせるためで、`anim.GAIT_TARGET` で決まる。
  `Idle` は呼吸と髪の揺れ、`Walk` は腰のひねりと腕振り、`Wave` は手を振りながら
  `smile` を同時にキーフレームする。
- 走りの腕は肩の片振幅 33 度・肘 72〜88 度（`Gait.__init__` の `arm` / `elbow`）。
  以前は肩 ±52 度で、拳が鎖骨（mirai で Z 1.111 m）まで跳ね上がる大振りだった
  （#43）。いまは手の最高到達がみぞおち（Z 0.975 m）に収まる。
  `anim.make_action` はフレームごとに `scene.frame_set(f)` してから姿勢を作って
  キーを打つ。順番を逆にすると、`frame_set` が打ち済みのキーで姿勢を上書きし、
  全キーが 1 キー目と同じ姿勢になる（脚が止まったまま滑る）。
- **表情をアーマチュアの Action と同じテイクに入れる方法。** Shape Key は
  別データブロックなので、素の Action のままでは FBX の同じ AnimStack に
  同居しない。`Head` ボーンにカスタムプロパティ `sk_<キー名>` を作り、
  Shape Key の `value` にそれを読むドライバを張ってから、ボーンの回転と一緒に
  プロパティをキーフレームする。FBX エクスポータは Action ごとにシーンを
  評価して焼くので、`Armature|<名前>` と `Key|<名前>` が対で書き出される。
- Blender 4.4 以降はスロット付き Action なので、`act.fcurves` が空のときは
  `act.layers[].strips[].channelbags[].fcurves` から辿る（`anim._fcurves`）。

## 検証

`--no-verify` を付けない限り、書き出した FBX を空シーンへ読み直して
メッシュ数・アーマチュア数・三角形数・Z 範囲・Action 6 本・シェイプキー 7 種・
ボーン名を印字し、`docs/DESIGN.md` §2.1 との差分（`contract_missing` / `extra`）
と、表情カーブが期待どおり入っているか（`Idle:blink_L+blink_R`,
`Talk:mouth_a+mouth_i`, `Wave:smile`）を出す。FBX の AnimStack 名は
`<Armature名>|<Action名>` になり再インポートでもう一度前置されるため、
`rsplit("|", 1)[-1]` で正規化して比較する。

## モジュール構成

| ファイル | 役割 |
|----------|------|
| `kcd_chara/params.py` | キャラ定義（寸法・色・顔レイアウト・衣装）と体型レベル。寸法は頭幅を 1 とする比 |
| `kcd_chara/mesh.py` | `MeshBuilder`。リング・チューブ・球・角丸箱と平行移動フレーム、パート名による頂点範囲の記録 |

## 既知の問題

- **走りの最大開脚フレームで、布から素肌がわずかに出る。** Walk / Run の腿が
  いちばん開くフレームで実測（レストで衣装の内側に完全に隠れている素肌頂点が、
  ポーズ後に衣装の外へ出た距離）:
  mirai のスカート 0.00 / 1.52 cm（3 頂点）、kaname のエプロン 0.00 / 0.35 cm、
  prof の白衣 3.28 / 3.54 cm、botchan の袴 5.18 / 6.68 cm、
  madonna の袴 2.60 / 3.99 cm。
  原因は形状のほうで、筒 1 本の袴・スカートを Hips ＋ 脚 1 本で包む以上、
  前後の中央は必ず Hips に張り付く（そうしないと隣り合う頂点が逆の脚に引かれて
  布が裂ける）。袴を左右 2 本に割った馬乗袴の形にするのが本筋の直し方。
- 眉が前髪に隠れる（上記のとおり Unity 側シェーダで解く前提）。
- `mirai` / `inari` のセーラー襟が平たい板で、下端が直線的。
- `inari` のツインテールが水平に張り出して見える。
- 側面図で横髪・前髪が顔の前に重なり、表情が見えにくい。
- 手が指の長い白い棒状に見える。
- `madonna` のリボンが横から見ると平たい多角形になる。
- `madonna` の袖の矢絣が UV スケールの違いで胴より大きく出る。
- 肩ヨークと袖の付け根の境に 1〜2 px の段差が残る。
